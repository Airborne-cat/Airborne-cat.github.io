###### - Large-Scale Distributed Training(On GPUs)

> **하나의 GPU로 학습하기 어려울 만큼 큰 모델을 여러 GPU로 어떻게 효율적으로 학습시킬 것인가?**

Gpu 연산 병목 요소
- **Compute**: GPU의 연산 능력을 얼마나 활용할 수 있는가?
    --> **다른 GPU 연산 대기로 인한 병목**
- **Memory**: 모델 파라미터, Activation, Gradient 등을 GPU 메모리에 저장할 수 있는가?
	--> **메모리 부족으로 인한 병목**
- **Communication**: 여러 GPU가 데이터를 주고받을 때 얼마나 많은 시간이 소요되는가?
	--> **GPU 사이의 통신 시간 병목**

이러한 병목을 해결하기 위한 하드웨어/소프트웨어적 솔루션을 해당 강의에서 소개함.

# 1. GPU 구성 요소

<img src="{{ '/assets/img/obsidian/cs231n-lecture-11/Pasted%20image%2020261105163426.png' | relative_url }}" alt="Pasted image 20261105163426" width="453">

- GPU 연산 능력 지표 == **FLOPS(Floating Point Operations Per Second)**
- Tensor Core: NVIDIA GPU 전용 행렬 연산 하드웨어
	--> 행렬의 곱셈 및 누적 연산($D = A \times B + C$)을 한 클록(Clock) 주기에 한 번에 수행
- BF16/FP16 부동소수점 포멧 방식 혼용

### - Tensor Core와 FP16/BF16의 결합: 혼합 정밀도 (Mixed Precision) (과정 외)
<img src="{{ '/assets/img/obsidian/cs231n-lecture-11/Pasted%20image%2020261105165918.png' | relative_url }}" alt="Pasted image 20261105165918" width="700">
NVIDIA GPU는 행렬 연산 시 FP16 또는 BF16으로 값을 받아 연산을 빠르게 수행하고 최종 누적 연산은 FP32로 처리
###### - 효과
- **VRAM 대역폭 및 메모리 절감:** 모델 가중치와 그래디언트의 데이터 크기가 절반으로 줄어들어 더 큰 배치 크기(Batch Size)를 사용 가능.
- **연산 스루풋(Throughput) 증대:** Tensor Core가 16비트 행렬 연산을 전용 파이프라인으로 처리하므로 FLOPS 성능 극대화.
- **정밀도 유지:** 누적 단계에서는 FP32를 사용하여 수치적 불안정성(Gradient Vanishing/Explosion)을 방지합니다.
